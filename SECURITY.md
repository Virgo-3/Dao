# Security boundaries

Dao is intended for a trusted single user on a local machine. Its HTTP listener binds only to `127.0.0.1`. Do not expose it through a public reverse proxy or port forwarding; it has no multi-user authentication or tenant isolation.

The browser must supply a process-scoped CSRF token to mutate state. Host, Origin, and cross-site fetch checks defend the local endpoint against browser-origin attacks. Static files are allowlisted, request bodies are bounded, and user/model content is rendered as text. API keys are read from environment variables and excluded from state/export/browser configuration. Database state and exports contain conversation data and should be treated as private.

The live provider endpoint is fixed to HTTPS OpenAI Responses. The API key is transmitted for provider authentication. The model can evaluate decisions, remember low-impact conversation context, and stage advanced structure proposals for operator review. It has no tools to accept or reject proposals, resolve conflicts, control branches, execute commands, read arbitrary files, send messages, or perform external actions. Explicit conversational navigation and unambiguous proposal review are handled by the local runtime from the current user message. Audit-gated artifacts are named content stored only in Dao's database.

Routine conversational capture accepts only new nodes and relations grounded to exact passages of the current user message. It validates stance so tentative, quoted, hypothetical, or negative statements do not become affirmative decisions. Relations must have `severe: false` and `actions: []`; the capture path cannot set beliefs, report observations, resolve conflicts, alter action scopes, or edit existing definitions. This path saves local notes without proposal review. It does not verify claims or infer that two statements are incompatible. Recognized local phrases require no provider request or token budget; unknown language goes to the configured demo or live provider. Advanced imports and explicit relationship operations retain their existing operator permissions.

Evidence is untrusted operator-supplied data. The adjudicator uses explicit source-count/reliability rules and contradicting evidence vetoes approval. This does not establish evidence truth or source independence. The latest verdict must match exact artifact content; a prior approval does not override a newer contradiction.

Structure proposals and their citations are untrusted data. Every proposed operation must cite an exact passage from a nonfailed message in the selected checkpoint; matching text establishes provenance, not factual truth or entailment. Proposal review requires the normal expected branch head and unchanged base graph digest, whether initiated through the operator mutation endpoint or an explicit unambiguous conversational request. Acceptance validates and applies the whole candidate atomically. Staging leaves accepted relationships unchanged. Failed turns restore their prior graph and proposals; completed semantic activities are stored with the assistant reply and emitted only after durable finalization. Accepted structure, recent activity summaries, and pending proposals are supplied to the model at user priority.

Conversational branch creation and switching validate names and check expected source and target heads. Final source replies and destination navigation are committed atomically. Switching appends the control turn to the target's own state; it does not copy semantic state from the source branch. The initial user message is committed separately so a failed finalization retains the attempted request. Restoring or branching can intentionally recover earlier policy state; these are explicit local operator actions, with journal history retained.

Relationship records and observations are also operator-supplied data. They are passed to the model at user-message priority, outside developer instructions. Relation definitions are immutable and bounded. Any negative belief probability or reported negative before/after state opens or reopens a conflict, which remains open after a positive, neutral, or unknown reassessment. Resolution requires a current graph-bound audit verdict, an assessed belief with zero negative probability, and no latest negative reported outcome. The runtime constructs resolution verdicts; imported JSON cannot supply them. Unresolved severe conflicts exclude their declared action names from both prior and posterior calculations. Action applicability is declared by the operator, not inferred or independently verified. Artifact permission requires a verdict without an action scope, checks every unresolved severe conflict, and binds the current relationship graph digest. Graph edits require a new audit. These policies grant no external-action permission and do not establish that an effect occurred.

Hash-linked revisions and journal entries provide consistency checks, not cryptographic authentication against a database owner. An attacker with local write access can replace the database and recompute hashes. Truncation to a consistent older backup needs an externally anchored digest to detect. Process restarts retain outstanding usage reservations. Unknown failed calls are conservatively charged for admission accounting; monetary costs remain estimates.

Security review should focus on HTTP ingress, origin/CSRF handling, content rendering, model/tool trust boundaries, cross-branch adjudication, optimistic concurrency, credential leakage, accounting on failed streams, and database integrity. Authentication for a public deployment, external tool effects, and provider-side billing accuracy are outside the implemented release's scope.

For vulnerability reporting, send the maintainer a private report through GitHub's private reporting feature if enabled. Avoid posting API keys, conversation databases, or private exports in public issues.
